# 09b. 전원 손실 강건성

## 목적

플래시 소거/기록 중에 전원이 끊겨도 **부팅 불가 상태가 되지 않게** 한다.
그리고 그것을 **증명**한다.

## 원칙 — 커밋은 마지막 한 번의 쿼드워드 프로그램

쿼드워드(16B) 프로그램은 원자적이고 ~40µs 다. 섹터 소거는 ~2ms 로 50배 길다.
따라서 **"유효/무효를 가르는 값" 은 반드시 마지막 단일 쿼드워드에 몰아넣는다.**

`firm_tag_t` 의 배치가 정확히 맞아떨어진다.

```
offset 0x00  magic_number | fw_addr | fw_size | fw_crc   <- 16B. 검증에 필요한 전부
offset 0x10  tag_crc + padding                            <- 16B
```

`0x00` 쿼드워드 하나를 마지막에 쓰면 그것이 완벽한 커밋 마커가 된다.

## 쓰기 지점별 순서

| 지점 | 순서 |
|---|---|
| UF2 / cmd 수신 완료 | ① `boot_slot_t`(0x020) → ② `tag_crc`(0x010) → ③ **`firm_tag_t` 첫 쿼드워드(0x000) = 커밋** |
| 슬롯 → FIRM 적용 | ① 본문(0x400~) → ② `boot_slot_t`(0x020) → ③ `tag_crc`(0x010) → ④ **커밋(0x000)** |
| 슬롯 무효화 | ① 무효 마커 쿼드워드(0x030) → ② 첫 섹터 소거 |
| 부트 로그 | ② 둘째 쿼드워드 → ① **magic 쿼드워드 = 커밋** |

`bootApplySlot()` 에서 오프셋 0부터 순차 복사하면 **TAG 가 가장 먼저 기록되어**
"TAG 유효 + 본문 미완성" 상태가 생긴다. 본문을 먼저 복사해야 한다.

## 소거 순서가 만들어내는 안전성

UF2 페이로드 오프셋 0 은 슬롯 베이스 + `0x400` = 그 슬롯의 **섹터 0** 이다.
첫 블록이 섹터 0 을 지우면서 **옛 태그가 함께 지워진다.** 그래서:

- 수신 중 전원이 끊기면 태그가 없어 그 슬롯은 무효로 판정된다
- 반대편 슬롯(현재 FIRM 의 백업본)과 FIRM 은 온전하다

## ECC 2비트 오류

지워진 영역(`0xFF`)은 유효 ECC 라 읽어도 안전하다. 문제는 **프로그램 도중 전원이
끊겨 반쯤 기록된 쿼드워드**다. 읽으면 ECC 2비트 오류로 **NMI** 가 난다.

기존 `NMI_Handler` 가 `while(1)` 이라 그대로 두면 **부트로더가 영영 멈춘다.**
오류 위치를 백업 레지스터에 남기고 리셋하도록 교체했다. 자세한 내용은
`03-flash-driver.md`, 정리 로직은 `09-fault-recovery.md`.

## 증명 — 호스트 전수 시뮬레이션

실기에서는 전원 차단 타이밍을 제어할 수 없어 운에 맡겨야 한다. 목 플래시에서는
**n 번째 플래시 연산 직후를 정확히 노릴 수 있다.**

```bash
cd firmware/stm32h5-boot/test/host && ./run.sh
```

`mockFlashFailAfter(n)` 으로 n 을 0부터 전체 연산 수까지 돌리며 각 지점마다
세 가지를 확인한다.

1. **불변식** — FIRM 또는 슬롯 중 최소 하나는 유효 (부팅 불가 상태가 없어야 한다)
2. **복구 가능성** — 다음 부팅에서 유효 슬롯을 재적용하면 정상이 되어야 한다
3. **중간 상태 금지** — "TAG 유효 + 본문 CRC 불일치" 가 나오면 커밋 순서가 틀린 것이다.
   `bootVerifySlot()` 이 `ERR_BOOT_FW_CRC` 를 돌려주는 것 자체가 그 신호다.

목 플래시는 동작을 흉내내는 것이 아니라 **STM32H5 제약을 강제**한다. 위반이 하나라도
있으면 테스트가 실패한다.

- 소거 단위 8KB, 프로그램 단위 16B
- 16B 정렬이 아닌 기록 거부
- **이미 프로그램된 쿼드워드 재기록 거부** (실기에서는 HAL 이 `HAL_OK` 를 반환하고
  ECC 만 조용히 깨진다)
- `FLASH_PROTECT_*` 영역 기록 거부

## 실측 결과

`bootApplySlot()` 의 **1540개 중단 지점 전부** 통과했다.

```
[test_powerloss]
  bootApplySlot() 플래시 연산 1540회 -> 전 지점 시뮬레이션
=== 44 passed, 0 failed ===
```

부트 로그 기록 중단도 전 지점 통과한다. 이 시험이 실제로 버그를 하나 잡았다
(`bootLogScanSect()` 가 빈틈에서 멈추던 문제, `09-fault-recovery.md` 참조).

## 실기 전원 차단 시험 (수동)

목이 커버하지 못하는 것은 **ECC 오류의 실제 발생**이다. SWD 로 인위적으로 만들 수 있다.

```bash
PROG=/opt/ST/STM32CubeCLT_1.21.0/STM32CubeProgrammer/bin/STM32_Programmer_CLI
# 이미 기록된 주소에 다시 쓰면 ECC 가 깨진다
$PROG -c port=SWD mode=HOTPLUG -w32 0x08100000 0xDEADBEEF
```

그 상태에서 `flash read 0x08100000 16` 을 실행하면 NMI 가 발생하는데,
**멈추지 않고 리셋된 뒤 다음 부팅에 해당 슬롯이 정리되어야** 한다.

USB 전원을 물리적으로 끊는 시험은 `uhubctl` 지원 허브가 있으면 자동화할 수 있다.
없으면 손으로 뽑았다 꽂으며 아래를 확인한다.

1. UF2 수신 중 차단 → 그 슬롯만 무효, 반대편 슬롯과 FIRM 은 온전
2. 적용 중 차단 → 다음 부팅에 소스 슬롯에서 자동 재적용
3. 로그 기록 중 차단 → 기존 레코드 보존, 다음 기록이 다음 자리로
