# 20. MAC 을 칩 고유번호에서 만든다

## 목적

보드를 두 장 이상 같은 망에 올릴 수 있게 한다.

## 문제

원래 소스에 MAC 이 박혀 있었다.

```c
.mac = {0x00, 0x00, 0x12, 0x34, 0x56, 0x78},
```

보드가 하나일 때는 아무 일도 없다. 두 장이 되면 **같은 MAC 이 두 개** 생긴다.
mDNS 이름이 겹치는 것과는 차원이 다르다.

- 스위치의 MAC 테이블이 두 포트 사이에서 뒤집힌다
- ARP 캐시가 어느 쪽을 가리킬지 모른다
- DHCP 서버가 같은 클라이언트로 보고 **같은 IP 를 두 장에 줄 수 있다**

mDNS 이름 충돌을 어떻게 풀지 이야기하다가 드러났다. 이름보다 이게 먼저다.

## 방법

STM32 UID 는 96비트이고 칩마다 다르다. 거기서 만든다.

```
[0] 0x02   bit1=1 locally administered, bit0=0 unicast
           제조사에서 산 OUI 가 아니므로 이 표시가 필요하다
[1] 0x00   우리 보드 표시용 고정
[2] UID[0] 웨이퍼 X - 다이마다 다르다
[3] UID[1] 웨이퍼 Y
[4] [5]    UID 12바이트 전체의 CRC16 - 로트가 달라도 갈린다
```

실측 : `02:00:46:00:D2:FC`

## 함정 : UID 는 워드로만 읽힌다 ← 하드폴트

처음에 UID 주소를 `utilCalcCRC()` 에 그대로 넘겼다. 그 함수는 `uint8_t` 로 훑는다.
**하드폴트가 났다.**

```
Fault Message
  Msg  : HardFault
  R1   : 0x08FFF800      <- UID_BASE
  R2   : 0x08FFF800
  R3   : 0x08FFF800
  PC   : 0x08028442      <- utilCalcCRC 안
```

`bsp.c` 의 `mpuInit()` 이 이 영역을 non-cacheable 로 잡아 접근이 버스로 바로
나가는데, **이 영역은 워드 단위만 받는다.**

대조가 되는 코드가 이미 있었다. `usbd_desc_cmp.c` 는 `*(uint32_t *)` 로 읽고
멀쩡하다. 그래서 워드로 지역 버퍼에 옮긴 뒤 거기서 계산한다.

```c
uid[0] = *(volatile uint32_t *)(UID_BASE + 0);
uid[1] = *(volatile uint32_t *)(UID_BASE + 4);
uid[2] = *(volatile uint32_t *)(UID_BASE + 8);
memcpy(buf, uid, sizeof(buf));
crc = utilCalcCRC(0, buf, sizeof(buf));
```

## 덤으로 확인된 것 : 롤백이 실제로 동작했다

이 하드폴트 때문에 앱이 부팅 직후 계속 죽었다. 그 사이에 **롤백 기구가 설계대로
돌았다.**

```
[  ] bootApplySlot(1) 189 KB
[OK] MODE_BIT_UPDATE slot1 err 0x0000     <- 적용은 성공
[  ] bootJumpFirm()
[ Firmware Begin... ]                     <- 새 펌웨어가 뜨고
[OK] usbBegin()  USB_CMP                  <- 여기서 죽는다
[ Bootloader Begin... ]                   <- 다시 부트로더
   ... 3회 반복 ...
```

3회 확정 실패 뒤 옛 이미지로 되돌아갔고, **실패한 슬롯은 무효화**됐다.
`boot info` 에서 SLOT1 이 `valid=0` 인 것이 그 흔적이다.

일부러 만든 상황이 아니라 진짜 사고였는데 설계대로 살아남았다. 타깃 테스트가
`noconfirm.bin` 으로 흉내내던 시나리오가 실제로 일어난 셈이다.

## MAC 이 바뀌면 IP 도 바뀐다

DHCP 서버는 MAC 으로 리스를 묶는다. MAC 을 바꾼 뒤 첫 부팅에서 **새 IP** 를 받는다.

```
172.30.1.57  ->  172.30.1.93
```

그래서 MAC 을 바꾼 펌웨어를 이더넷으로 올리면 **올린 뒤 그 IP 로는 못 찾는다.**
스캔으로 다시 찾아야 한다.

```bash
python3 tools/net/discover.py
```

## 다음 : mDNS 이름

MAC 이 고유해졌으므로 이름도 거기서 만들면 충돌이 없다.

| 방식 | 결과 |
|---|---|
| 전부 `stm32h5.local` | 두 보드가 같은 질의에 응답한다. 먼저 답한 쪽이 잡히고 조회할 때마다 바뀔 수 있다 |
| RFC 6762 대로 probe 후 개명 | 두 번째 보드가 스스로 `stm32h5-2.local` 이 된다. 충돌은 없지만 어느 게 어느 건지 모른다 |
| **MAC 에서 만든 고유 이름** | `stm32h5-d2fc.local`. 충돌이 없고 보드마다 고정이다 |

세 번째로 간다. NVS(로드맵 D)가 생기면 사용자가 이름을 직접 정할 수 있게 한다.

다만 mDNS 가 주는 것은 **"IP 를 몰라도 주소창에 칠 수 있다"** 하나다. 브라우저에서
**목록을 얻는 것은 여전히 불가능**하다(JS 에 mDNS API 가 없다). 보드를 찾는 일
자체는 이미 스캔이 더 잘 푼다 - 비컨에 이름·버전·모드가 다 실려 온다.
